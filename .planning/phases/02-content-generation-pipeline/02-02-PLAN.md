       - Add `CLAUDE_DELAY_MS = 1000` (Claude has higher rate limits, 1s is sufficient)

    3. **Generation loop:** For each city/service pair:
       ```
       Step 1: Build research prompt → call geminiResearch → get ResearchOutput
       Step 2: Call claudeWrite(research, city, service) → get content with FAQs
       Step 3: Assemble GeneratedContent with metadata (both model names)
       Step 4: Write JSON file (same path logic as before)
       ```

    4. **Rate limiting:** After each pair, delay `DELAY_MS` (Gemini is the bottleneck). The Claude call happens between Gemini calls so it naturally spaces them out.

    5. **Word count:** Update `countWords` to include FAQ answers in the word count:
       ```typescript
       const faqText = result.faqs.map(f => f.answer).join(' ');
       const wordCount = countWords([result.intro, result.serviceDescription, result.localContext, result.whyChooseUs, faqText].join(' '));
       ```

    6. **Metadata:** Update to use dual-model metadata format:
       ```typescript
       metadata: {
         citySlug: city,
         serviceSlug: service,
         generatedAt: new Date().toISOString(),
         researchModel: RESEARCH_MODEL,
         writingModel: WRITING_MODEL,
         wordCount,
       }
       ```

    7. **Error handling:** Keep existing try/catch. If Gemini step fails, skip Claude step (already handled by sequential flow). Log which step failed: "FAILED (research): ..." or "FAILED (writing): ...".

    8. **Progress logging:** Update to show both steps:
       ```
       [5/240] burlingame/custom-carpentry — researching...
       [5/240] burlingame/custom-carpentry — writing...
       [5/240] burlingame/custom-carpentry (312 words, 4 FAQs)
       ```

    **Part B: Create `validate-content.ts`**

    New file. Import `compareTwoStrings` from `string-similarity`. Follow the validation pattern from 02-RESEARCH.md.

    Implementation:
    1. **Read all generated JSON files** from `nextjs-cf.design/content/generated/`
    2. **Group by service slug** — for each service, collect content from all cities
    3. **Compare each city pair** for the same service, checking these sections independently: `intro`, `serviceDescription`, `localContext`
    4. **Flag pairs with Dice coefficient > 0.7** as potentially too similar
    5. **Also check for thin content** — flag any page with total word count < 200
    6. **Also check for missing FAQs** — flag any page with fewer than 3 FAQs
    7. **Output a summary table** to stdout:
       ```
       SIMILARITY FLAGS (threshold: 0.7):
       burlingame vs san-mateo | custom-carpentry | intro | 0.82
       ...

       THIN CONTENT (< 200 words):
       menlo-park/deck-construction — 145 words

       MISSING FAQS (< 3):
       redwood-city/painting — 2 FAQs

       Total: X flags, Y thin, Z missing FAQs
       ```
    8. **Exit code 1** if any flags found (for CI integration), exit 0 if clean
    9. Add a `--threshold` flag (default 0.7) to customize similarity sensitivity

    **Script registration:** The package.json already has `"validate": "tsx scripts/validate-content.ts"` — no change needed.

    **What NOT to do:**
    - Do NOT change the output directory path — keep `nextjs-cf.design/content/generated/`
    - Do NOT remove the --force, --city, or --dry-run flags from generate-content.ts
    - Do NOT add artificial delays between Gemini and Claude calls (they're sequential, not parallel)
