**scripts/lib/schemas.ts** — Define the GeneratedContent TypeScript interface and the Gemini responseSchema:

```typescript
import { Type } from '@google/genai';

export interface GeneratedContent {
  intro: string;
  serviceDescription: string;
  localContext: string;
  whyChooseUs: string;
  highlights: string[];
  metadata: {
    citySlug: string;
    serviceSlug: string;
    generatedAt: string;
    model: string;
    wordCount: number;
  };
}

export const contentSchema = {
  type: Type.OBJECT,
  properties: {
    intro: {
      type: Type.STRING,
      description: 'Opening paragraph mentioning the city by name, key neighborhoods, and how the service fits the local context. 60-80 words.',
    },
    serviceDescription: {
      type: Type.STRING,
      description: 'Detailed description of the service tailored to the city. Reference local housing stock, common project scenarios, and materials suited to the climate. 80-120 words.',
    },
    localContext: {
      type: Type.STRING,
      description: 'Why this service matters specifically in this city. Reference permits, HOA considerations, neighborhood character, and relevant landmarks. 60-80 words.',
    },
    whyChooseUs: {
      type: Type.STRING,
      description: 'Why cf.design is the right choice for this service in this city. Mention Peninsula expertise, nearby completed projects, and local knowledge. 40-60 words.',
    },
    highlights: {
      type: Type.ARRAY,
      items: { type: Type.STRING },
      description: '3-4 bullet points highlighting key benefits, each 10-20 words.',
    },
  },
  required: ['intro', 'serviceDescription', 'localContext', 'whyChooseUs', 'highlights'],
};
```

**scripts/lib/prompts.ts** — Build rich prompts from Phase 1 data:

Import `getPageData` from `../../data/helpers`. Create `buildPrompt(citySlug: string, serviceSlug: string): string` that:
1. Calls `getPageData(citySlug, serviceSlug)` — throw if null
2. Injects ALL local knowledge: city name, county, neighborhoods (joined), characteristics (joined), housing stock (semicolon-joined), landmarks (semicolon-joined), climate notes, permits (semicolon-joined), HOA notes
3. Injects service context: title, longDescription, relatedServices (joined)
4. Injects nearby case studies: title, location, description for each
5. Sets tone: "professional but approachable, confident but not salesy"
6. Requirements: mention specific neighborhoods/landmarks/housing by name, reference permits/HOA where relevant, no generic filler, 250-350 words total
7. Follow the prompt template from 02-RESEARCH.md Pattern 2 closely

**scripts/lib/gemini.ts** — Gemini client setup:

Import `GoogleGenAI` from `@google/genai`. Import `dotenv/config` to load .env. Import `contentSchema` and `GeneratedContent` from schemas.

Create `generateContent(prompt: string): Promise<Omit<GeneratedContent, 'metadata'>>` that:
1. Initializes GoogleGenAI with `process.env.GEMINI_API_KEY` (throw clear error if missing)
2. Calls `ai.models.generateContent()` with model `gemini-2.5-flash`, the prompt as contents, and config with `responseMimeType: 'application/json'` and `responseSchema: contentSchema`
3. Parses `response.text` as JSON and returns it
4. Wraps in retry logic: on 429 errors, retry up to 3 times with exponential backoff (2s, 4s, 8s). On other errors, throw immediately.

**.env.example** — Create with placeholder:
```

```

Do NOT create a .env file (it's gitignored and user must create it manually).

<task type="auto">
  <name>Task 2: Create the main generation script with rate limiting and idempotency</name>
  <files>scripts/generate-content.ts</files>
  <action>
Create `scripts/generate-content.ts` — the main entry point run via `npx tsx scripts/generate-content.ts`.

Import: `getAllCityServiceParams` from `../data/helpers`, `buildPrompt` from `./lib/prompts`, `generateContent` from `./lib/gemini`, `GeneratedContent` from `./lib/schemas`, `fs` and `path` from Node builtins.

Implement:
1. **CLI flags:** Parse `process.argv` for:
   - `--force` — regenerate all, ignoring existing files
   - `--city {slug}` — only generate for one city (11 files)
   - `--dry-run` — print what would be generated without calling API
2. **Rate limiting:** 8-second delay between API calls (~7.5 RPM, stays under 10 RPM free tier limit)
3. **Idempotent re-runs:** Skip files that already exist at `content/generated/{city}/{service}.json` (unless --force)
4. **Output path:** `content/generated/{city}/{service}.json` — create directories with `fs.mkdirSync(dir, { recursive: true })`
5. **Metadata enrichment:** After receiving Gemini response (which has intro, serviceDescription, localContext, whyChooseUs, highlights), add `metadata` field with: citySlug, serviceSlug, generatedAt (ISO string), model ('gemini-2.5-flash'), wordCount (count words across intro + serviceDescription + localContext + whyChooseUs)
6. **Word count validation:** If total word count < 200, log a WARNING but still save the file (validation script in 02-02 will flag it)
7. **Progress logging:** Log `[N/total] city/service ✓` after each generation, and `[N/total] city/service (skipped)` for existing files
8. **Summary:** At end, log total generated, skipped, warnings (under word count), and elapsed time
9. **Error handling:** If a single page fails after retries, log the error and continue to next page (don't crash the whole run). Track failures and report count at end.

Write JSON with `JSON.stringify(content, null, 2)` for readable committed files.

The `delay` function: `const delay = (ms: number) => new Promise(resolve => setTimeout(resolve, ms))`
